# ACTIVSg500 GPU Lagrangian experiment v3

V3 preserves the v2 ACTIVSg500 model, raw-input hashes, exact source `PMIN`
values, tolerances, FP64 coefficient cleanup, GPU PDLP/Lagrangian algorithms,
and previously hashed laptop HiGHS comparison. It changes only orchestration
after v2 allowed one numerically stalled fixed-commitment repair to consume
almost the entire 600-second run.

## Durable lower-bound evidence

The root restricted-master solution, exhaustive contingency screen, GPU
Lagrangian leaf certificate, and independent CPU replay are checkpointed before
any fixed-commitment repair starts. A disjunctive split is transactional: the
parent remains the certified frontier leaf while both children are solved. The
parent is replaced only after both child certificates exist, after which the
new exhaustive leaf cover is independently replayed and checkpointed. A
deadline or solver failure during either child therefore leaves the last valid
global lower-bound certificate intact.

The CPU replay is an independent verifier of GPU-produced evidence, not an LP
solver or branch-and-bound engine. The lower-bound search itself remains GPU
resident and uses cuOpt PDLP plus CuPy FP64 Lagrangian evaluation.

## Bounded primal-candidate queue

Each unique fixed-commitment repair receives at most 15 seconds in cuOpt PDLP,
divided into slices of at most 5 seconds. A time-limited vector may warm-start
the next slice on the same canonical model. When contingency rows are appended,
the unchanged primal vector is reused and the prior dual vector is
deterministically zero-extended for the new rows.

A candidate is rejected early if its dual-objective magnitude reaches one
million times the primal-objective scale, or if two consecutive infeasible
iterates improve the canonical primal residual by less than one percent. A
candidate result that is mathematically infeasible is logged and abandoned;
adapter errors, malformed vectors, and other unexpected model/solver failures
remain fatal and are not relabeled as candidate rejection. The global deadline
exception is also always propagated.

The deterministic initial queue is:

1. root PDLP commitment rounded at 0.5;
2. the minimizing binary commitment generated by the root GPU Lagrangian loop;
3. root PDLP commitment thresholded at 0.25;
4. all source-online generators committed.

Capacity repair may only change a proposal enough to satisfy aggregate exact
`PMIN`/`PMAX` demand bounds. Every unique submitted commitment records its
source generator rows, hash, capacity-repair changes, and on/off transition
from the preceding candidate. If disjunctive refinement is needed and repair
capacity remains, child LP rounding can add later deterministic candidates.

## Acceptance and run policy

The one v3 full-model DGX Spark execution has the same 600-second global
deadline and `1e-3` requested relative gap. Success still requires a secure
fixed-commitment primal, exhaustive zero-violation contingency verification,
an independently replayed disjunctive Lagrangian lower bound, and the requested
gap. The run uses no integer solver and no CPU branch-and-bound. A candidate
timeout, a retained root certificate, or stable commitment by itself is not
success.

Development is limited to tiny fixtures and a DGX smoke test. The v2 one-shot
files and frozen tag remain immutable. V3 is frozen under
`experiment-500-gpu-lagrangian-v3` before its sole full ACTIVSg500 execution.
